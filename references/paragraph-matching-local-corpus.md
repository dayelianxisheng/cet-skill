# 本地题库：段落匹配专项

本流程仅用于用户拥有或明确授权的本地题库。当前只开发 `question_type = matching`；其他题型以后分别设计，不能直接套用本流程。

## 核心准则：先验证，再固化

画线准则必须来自数据库验证，不能凭直觉新增为核心规则。当前数据库共有420道段落匹配题，全部具有答案字母和对应证据段落。2025年12月与2026年6月的60题答案来自用户提供的4份PDF，已逐题完成“PDF答案—数据库题干—数据库段落”三方核对。

固定按时间拆分有标签数据：

- 训练集：2020—2023，270题；
- 验证集：2024，60题；
- 测试集：2025—2026，90题。

运行 `scripts/evaluate_matching_anchors.py` 复核准则。训练和迭代只能使用训练集与验证集；测试集用于阶段性最终检查。不得用无标签数据伪造准确率。

当前420题基准结果：

- 基础锚点法：验证集Top-1 81.7%、Top-3 93.3%、Top-5 95.0%；测试集Top-1 68.9%、Top-3 87.8%、Top-5 96.7%；
- 邻词扩展法：验证集没有提高；
- 潜在语义法：验证集没有稳定提高，拒绝；
- 训练集改写词映射：训练集升高但验证集降至75.0%，属于过拟合，拒绝。
- 词形、短语及完整题干表面相似度：验证集没有超过基础锚点法，不能替代证据核验。
- 篇内稀有度、锚点覆盖率及完整题干词/字符相似度组合（v9/v10）：验证集Top-1 86.7%、Top-3 91.7%、Top-5 96.7%；时间外测试集Top-1 77.8%、Top-3 94.4%、Top-5 100.0%。

另使用文章正文指纹分组的六折交叉验证：420题对应39篇唯一文章，重复文章必须处于同一折，不能跨训练与验证。交叉验证最佳结果为Top-1 76.2%、Top-3 91.9%、Top-5 95.5%。最佳参数使用邻词保留锚点、篇内覆盖权重4、表面相似度权重8、单词与字符相似度各50%。给数字、逻辑词或专名额外加权没有提高，不纳入核心方法。

因此核心结论是：

> **画线的作用是召回3—5个候选段落，不是直接决定答案。**

锚点法只有在分组交叉验证和时间外测试中Top-5召回率均不低于95%时才可作为“候选召回规则”；Top-3仅作为诊断指标，不再作为通过标准。若要用于自动选答案，则Top-1必须不低于85%。当前分组交叉验证Top-5为95.5%，时间外测试Top-5为100.0%，候选召回通过；时间外测试Top-1为77.8%，自动选答不通过。因此禁止根据画线词或词面相同直接给出答案，必须在3—5个候选中执行后续证据核验。

时间外测试90题中，70题的正确段落排第1，15题排第2—3，5题排第4—5。最难题主要是整段关系短语改写，例如“不用付费 ↔ costs nothing/free”“不问薪资 ↔ pay is best avoided”“预防 ↔ delay/put off”“被吸引 ↔ come/visit”。这些例子用于人工核验提醒，不能作为已经验证的硬编码词典；新词典必须用未来未见数据重新验证。

任何规则修改都要重新运行评估。若验证集没有提高、测试集下降或训练集提高而验证集下降，应撤销该修改并记录为无效或过拟合方案。

## 数据范围与关系

按以下关系取数：

`exams → sections → passages → questions → answer_keys`

- 用 `level/exam_type + year + month + set_number` 唯一定位试卷。
- 用 `question_type = matching` 限定段落匹配题。
- `passages.content_text` 保存字母段落，作为匹配选项。不得硬编码为A—O；应从原文实际解析A—Z范围内的连续标签，因为数据库中存在到P段的试卷。
- `questions.stem_text` 保存题干，通常为 36—45。
- `answer_keys.answer_value` 保存段落字母，`answer_text` 保存证据段落。
- 读取时保留数据库中的题号、段落字母和排序；缺失或重复时报告，不猜测。

## 核心学习链条

每道题的完整逻辑链统一表示为：

`题干原句 → 题干定位锚点 → 候选段落 → 原文证据锚点 → 改写关系 → 匹配结论 → 错因标签`

题干定位锚点优先选择：

1. 独特主体：人名、机构、地点、专有名词；
2. 核心动作：发生、变化、拒绝、建议、发现等；
3. 对象或结果：动作指向的事物及最终结果；
4. 限定条件：时间、数字、比较、范围、程度；
5. 逻辑标志：因果、转折、否定、让步、目的。

不要把冠词、普通代词、宽泛名词或整句都画线。每题通常标2—4组锚点。每组必须是原题中连续的1—3个单词，优先单个高价值词，其次使用不超过3词的固定短语。画线结果用于形成3—5个候选段落，不能单独产生答案。

### 画线长度硬限制

- 一条画线最多3个英文单词；连字符词按1个词计算；
- 优先级：单个独特词 > 两词搭配 > 三词关系短语；
- 超过3词的关系必须拆分，例如 `stay away from city life` 拆为 `stay away` 与 `city life`；
- 只标原题中实际出现的连续文本，不在题干内发明同义词；需要抽象时，在题后另列单词标签；
- 每题默认2—4条线；只有数字、专名或极强定位词足够时可以只画1条；
- 不为了凑数量画主题词、冠词、普通代词或无区分度词。

合格示例：

`A 【well-known artist】 【failed to purchase】 a 【house】...`

不合格示例：

`A 【well-known artist failed to purchase a house】...`（单条超过3词）

原文证据锚点应与题干锚点逐组对应。不能只因一个词相同就判定；至少验证“主体 + 动作/关系”，必要时再验证对象、时间、数量、极性和范围。只有完成这一步才允许形成匹配结论。

文章展示后，候选扫描顺序采用两层规则：

1. 先找同一篇文章中较少出现的锚点组合，并允许词形变化；
2. 再比较完整题干与段落的单词和字符表面相似性；
3. 保留得分最高的3—5段进入人工核验；
4. 不给数字、逻辑词或专名机械追加固定权重，因为交叉验证未证明有效。

## 可见画线格式

当前聊天界面不可靠地渲染 `<u>...</u>`，因此禁止把HTML下划线作为默认输出。默认使用Unicode组合下划线：在被标记短语的每个可见字符后添加 `U+0332 COMBINING LOW LINE`。例如：

`w̲e̲l̲l̲-̲k̲n̲o̲w̲n̲ a̲r̲t̲i̲s̲t̲`

如果客户端不能稳定显示组合下划线，退化为不会丢失的边界标记：

`【well-known artist】`

每次首次输出画线题时先显示一个短示例；用户确认哪种格式可见后，本轮统一使用该格式。不能继续输出用户已明确表示不可见的 `<u>` 标签。

## 逻辑类型

给每道题标注一个主类型，必要时附一个次类型：

- **事实改写链**：题干压缩或改写段落中的具体事实；
- **同义替换链**：关键词不同，但核心语义相同；
- **因果链**：题干与原文在原因、结果或目的之间转换；
- **比较链**：涉及相似、差异、更多、更少或历史类比；
- **时间变化链**：过去与现在、先后、持续时间或趋势变化；
- **数字数量链**：比例、次数、距离、年龄、年份或数量换写；
- **否定转折链**：not、failed、unable、little、unexpected 等极性信息；
- **观点建议链**：人物或机构的判断、担忧、建议、要求；
- **例证概括链**：题干把具体案例提升为概括性结论；
- **主体/指代链**：题干用身份、群体或代词替换原文主体。

## 运行阶段

### 阶段 0：定位与校验

1. 根据考试级别、年月和套数定位唯一 `exam_id`；
2. 确认存在 matching passage、题号和段落字母；
3. 检查题目数量、段落数量及排序；
4. 默认不读取答案。

### 阶段 1：题干盲画线

只读取 `questions`，不得读取 `passages`、`answer_keys` 或任何已标注证据。

输出：

1. 原题；
2. 带下划线题目；
3. 可选的锚点说明（主体/动作/对象/限定/逻辑）。

下划线默认使用Unicode组合下划线；不兼容时使用 `【...】`。这一阶段衡量的是“只看题干能否把正确段落召回到3—5个候选中”，不是能否直接猜中答案。

输出前逐条计数；任何标记超过3词都必须拆分或缩短后再显示。

### 阶段 2：展示段落选项

阶段1的标注冻结后，读取 `passages.content_text` 并按原顺序显示全部字母段落。不读取答案表，不突出任何段落，也不暗示正确选项。

默认显示顺序：

1. 段落选项；
2. 原题；
3. 带下划线题目。

若用户明确要求先练题干画线，可只显示第2、3项，待其确认后再显示段落。

### 阶段 3：用户作答

要求用户按 `36A 37F ...` 提交答案。此阶段仍不读取或显示答案表。

可记录：

- 作答字母；
- 犹豫的题目；
- 用户自选定位词；
- 用时。

### 阶段 4：答案与证据核验

用户提交后才能读取 `answer_keys.answer_value` 和 `answer_text`。

逐题输出：

1. 用户答案与正确字母；
2. 带下划线题干；
3. 正确段落中的带下划线证据；
4. “题干锚点 ↔ 原文证据”的逐组映射；
5. 主逻辑类型及次逻辑类型；
6. 一句话说明为什么匹配。

只给答案字母不算完成核验。

核验顺序固定为：

`主体一致 → 动作/关系一致 → 对象/结果一致 → 时间/数字/极性/范围一致`

任一关键条件冲突，都不能因为出现相同关键词而选择该段落。

### 阶段 5：错因诊断

错误至少归入一种：

- 定位词太泛；
- 只匹配相同单词，未验证语义；
- 漏看否定、比较、时间、数字或范围；
- 主体错配；
- 因果方向反转；
- 例子与结论混淆；
- 被相邻段落或主题相似段落干扰；
- 找到证据但字母抄错；
- 时间分配不当。

### 阶段 6：复盘与迁移

一套题结束后汇总：

- 正确率与用时；
- 各逻辑类型的正确率；
- 最常见错因；
- 用户遗漏的高价值锚点；
- 3—5组可复用的同义替换；
- 下一套训练只强化最弱的1—2类逻辑。

## 功能入口

识别以下意图：

- “画线练习 / 不看文章先画词” → 阶段1；
- “显示选项 / 显示文章” → 阶段2；
- 用户发送题号加字母 → 阶段3并进入阶段4；
- “显示对应内容 / 原文定位” → 阶段4；
- “为什么选这个 / 逻辑链” → 阶段4的映射与解释；
- “总结错因 / 复盘” → 阶段5—6；
- “下一套 / 随机一套” → 选择未练过的 matching 试卷并从阶段0开始。

## 输出约束

- 清楚标注当前阶段及是否读取答案；
- 每条画线严格限制为1—3个单词，并在输出前自检；
- 在答案揭示前，不能通过加粗、排序、提示语或只展示部分段落暗示答案；
- 题干画线与证据画线使用不同小节，不混成一段；
- 数据库文本保持原样，助手增加的说明单独标注；
- 用户要求“不要看答案”时，整个当前练习回合都不访问答案表；
- 数据不完整时停止该题核验并报告缺失字段。

## 后续扩展边界

未来可以为选词填空、仔细阅读、听力、翻译和写作分别新增引用文件。扩展时复用“定位—作答—核验—诊断—迁移”的上层框架，但必须重新定义各题型的数据表、证据单位、画线对象和错因分类；当前段落匹配规则不是通用实现。
