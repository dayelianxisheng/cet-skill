# 本地题库：段落匹配专项

本流程仅用于用户拥有或明确授权的本地题库。当前只开发 `question_type = matching`；其他题型以后分别设计，不能直接套用本流程。

用户可见的默认版式、模式切换、空白项处理和显示兼容要求，以 [paragraph-matching-output-contract.md](paragraph-matching-output-contract.md) 为唯一权威来源。每次生成段落匹配练习或核验输出前都必须读取该文件；不得要求用户重复描述已规定的版式。

## 核心准则：先验证，再固化

标记准则必须来自数据库验证，不能凭直觉新增为核心规则。当前数据库共有420道段落匹配题，全部具有答案字母和对应证据段落。2025年12月与2026年6月的60题答案来自用户提供的4份PDF，已逐题完成“PDF答案—数据库题干—数据库段落”三方核对。

固定按时间拆分有标签数据：

- 训练集：2020—2023，270题；
- 验证集：2024，60题；
- 测试集：2025—2026，90题。

运行 `scripts/evaluate_matching_anchors.py` 复核准则。训练和迭代只能使用训练集与验证集；测试集用于阶段性最终检查。不得用无标签数据伪造准确率。

当前420题基准结果：

- 基础锚点法：验证集Top-1 81.7%、Top-3 93.3%、Top-5 95.0%；测试集Top-1 68.9%、Top-3 87.8%、Top-5 96.7%；
- 邻词扩展法：验证集没有提高；
- 潜在语义法：验证集没有稳定提高，拒绝；
- 训练集改写词映射：训练集升高但验证集降至75.0%，属于过拟合，拒绝。
- 词形、短语及完整题干表面相似度：验证集没有超过基础锚点法，不能替代证据核验。
- 篇内稀有度、锚点覆盖率及完整题干词/字符相似度组合（v9/v10）：验证集Top-1 86.7%、Top-3 91.7%、Top-5 96.7%；时间外测试集Top-1 77.8%、Top-3 94.4%、Top-5 100.0%。
- 严格1—3词短语标记（v11）：验证集Top-1 83.3%、Top-3 90.0%、Top-5 96.7%；时间外测试集Top-1 76.7%、Top-3 94.4%、Top-5 98.9%，通过候选召回门槛。
- 纯单词标记（v12）：时间外测试集Top-1 66.7%、Top-3 91.1%、Top-5 94.4%，未达到95%门槛，拒绝作为默认规则。
- 严格每题两个锚点（v13）：验证集Top-5 91.7%、分组交叉验证Top-5 93.3%，不合格；不能把两个设为绝对上限。
- 最多三个锚点（v14）：验证集Top-5 98.3%、时间外测试Top-5 98.9%、分组交叉验证Top-5 95.0%。该实验说明三个锚点通常够用，但不是当前硬上限；用户明确要求低优先级可以分别保留主体、对象/结果和限定条件。
- 单一核心 `【】`、无辅助信息（v15）：验证集Top-5 90.0%、时间外测试Top-5 93.3%、分组交叉验证Top-5最高92.1%，明显低于95%门槛，拒绝。

另使用文章正文指纹分组的六折交叉验证：420题对应39篇唯一文章，重复文章必须处于同一折，不能跨训练与验证。交叉验证最佳结果为Top-1 76.2%、Top-3 91.9%、Top-5 95.5%。最佳参数使用邻词保留锚点、篇内覆盖权重4、表面相似度权重8、单词与字符相似度各50%。给数字、逻辑词或专名额外加权没有提高，不纳入核心方法。

因此核心结论是：

> **`【】` 标记的作用是召回3—5个候选段落，不是直接决定答案。**

锚点法只有在分组交叉验证和时间外测试中Top-5召回率均不低于95%时才可作为“候选召回规则”；Top-3仅作为诊断指标，不再作为通过标准。若要用于自动选答案，则Top-1必须不低于85%。严格1—3词短语标记的时间外测试Top-5为98.9%，候选召回通过；Top-1为76.7%，自动选答不通过。因此禁止根据 `【】` 内的词或词面相同直接给出答案，必须在3—5个候选中执行后续证据核验。

时间外测试90题中，70题的正确段落排第1，15题排第2—3，5题排第4—5。最难题主要是整段关系短语改写，例如“不用付费 ↔ costs nothing/free”“不问薪资 ↔ pay is best avoided”“预防 ↔ delay/put off”“被吸引 ↔ come/visit”。这些例子用于人工核验提醒，不能作为已经验证的硬编码词典；新词典必须用未来未见数据重新验证。

任何规则修改都要重新运行评估。若验证集没有提高、测试集下降或训练集提高而验证集下降，应撤销该修改并记录为无效或过拟合方案。

## 数据范围与关系

按以下关系取数：

`exams → sections → passages → questions → answer_keys`

- 用 `level/exam_type + year + month + set_number` 唯一定位试卷。
- 用 `question_type = matching` 限定段落匹配题。
- `passages.content_text` 保存字母段落，作为匹配选项。不得硬编码为A—O；应从原文实际解析A—Z范围内的连续标签，因为数据库中存在到P段的试卷。
- `questions.stem_text` 保存题干，通常为 36—45。
- `answer_keys.answer_value` 保存段落字母，`answer_text` 保存证据段落。
- 读取时保留数据库中的题号、段落字母和排序；缺失或重复时报告，不猜测。

## 核心学习链条

每道题的完整逻辑链统一表示为：

`题干原句 → 题干定位锚点 → 候选段落 → 原文证据锚点 → 改写关系 → 匹配结论 → 错因标签`

题干定位锚点优先选择：

1. 独特主体：人名、机构、地点、专有名词；
2. 核心动作：发生、变化、拒绝、建议、发现等；
3. 对象或结果：动作指向的事物及最终结果；
4. 限定条件：时间、数字、比较、范围、程度；
5. 逻辑标志：因果、转折、否定、让步、目的。

不要标记冠词、普通代词、宽泛名词或整句。每题标1个一级硬定位锚点，并按需要标1—3个二级语义核验线索，总计2—4组。每组必须是原题中连续的1—3个单词。`【】`用于先扫原文定位，下划线用于定位后比较；纯单词方案未通过测试，因此不能强制所有线索单词化。标记结果用于形成3—5个候选段落，不能单独产生答案。

### 两级优先级与数量标准

- 只设置两个优先级，不设第三级；
- **一级硬定位**：使用 `【...】`，原则上只标1处，用于快速扫描原文；
- **二级语义核验**：使用可见Unicode下划线，可分别标记核心动作/关系、对象/结果、关键限定条件，最多3处；
- 每题通常共2—4处：1个一级硬定位，加1—3个二级核验线索；
- 每处最多3个英文单词；连字符词按1个词计算；
- 短语形式优先级：单个独特词 > 两词搭配 > 三词关系短语；
- 超过3词的关系必须拆分，例如 `stay away from city life` 拆为 `stay away` 与 `city life`；
- 只标原题中实际出现的连续文本，不在题干内发明同义词；需要抽象时，在题后另列单词标签；
- 不为了凑数量画主题词、冠词、普通代词或无区分度词。

一级 `【】` 选择顺序：

1. 独特主体：人名、机构、地点、身份、专有名词；
2. 数字、年份、时间、距离、比例、引号内术语；
3. 具体且少见的名词短语；
4. 能稳定复现的对象或结果；
5. 若上述都没有，选择最不容易被同义改写的具体短语。

一级定位测试：

- 能否直接拿这1—3词快速扫过A—Z各段？
- 它是否比全文主题词更少见、更具体？
- 它是否可能以原词、词形变化或近似表面形式出现在原文？
- 若主语是全文反复出现的主题，例如每段都谈同一座岛、同一种饮料或同一家公司，不能仅因它是主语就放入 `【】`。

二级下划线内容：

- 核心动作或关系；
- 否定、因果、比较、变化或态度；
- 对象/结果；
- 时间、范围、方向和程度等剩余限定。

数据结论：固定给专名、数字或逻辑词增加机器权重没有稳定提高自动排序，因此不能机械地按词性决定答案；但从用户扫描原文的流程看，表面稳定的主体和具体名词更适合作为第一遍定位锚点，容易同义替换的关系短语更适合放在第二遍语义核验。

这一调整只交换同一组锚点的视觉优先级和使用顺序，不删除原有语义线索，因此既有Top-1/Top-3/Top-5召回基准仍可沿用；它优化的是人工扫描速度，不宣称提高自动排序准确率。

“只用 `【】`”必须区分两种情况：若仍保留相同的2—4个锚点，只是全部改用 `【】` 显示，检索准确率不变，但会失去“先定位、后核验”的操作提示；若每题只保留一个硬定位锚点，则按v15结果无法通过准确率门槛。当前标准因此保留一个 `【】` 与多个二级下划线。

合格示例（一级定位 + 二级核验）：

`A 【well-known artist】 f̲a̲i̲l̲e̲d̲ t̲o̲ p̲u̲r̲c̲h̲a̲s̲e̲ a h̲o̲u̲s̲e̲...`

不合格示例：

`A 【well-known artist failed to purchase a house】...`（单条超过3词且没有区分优先级）

原文证据锚点应与题干锚点逐组对应。先用题干与原文的 `【】` 找到候选位置，再用双方下划线核验动作/关系、对象、时间、数量、极性和范围。不能只因定位词相同就判定；只有完成第二遍语义核验才允许形成匹配结论。

文章展示后，候选扫描顺序采用两层规则：

1. 先用 `【】` 中的硬定位锚点扫描同一篇文章，并允许词形变化；
2. 找到候选位置后，再用下划线内容比较动作、关系、对象、结果和限定条件；
3. 保留得分最高的3—5段进入人工核验；
4. 不给数字、逻辑词或专名机械追加固定权重，因为交叉验证未证明有效。

## 可见标记格式

一级硬定位使用 `【...】`。二级语义核验可以有多个，统一使用Unicode组合下划线 `U+0332`，例如 `f̲a̲i̲l̲e̲d̲ t̲o̲ p̲u̲r̲c̲h̲a̲s̲e̲`。禁止使用无法稳定显示的HTML `<u>...</u>`。

## 逻辑类型

给每道题标注一个主类型，必要时附一个次类型：

- **事实改写链**：题干压缩或改写段落中的具体事实；
- **同义替换链**：关键词不同，但核心语义相同；
- **因果链**：题干与原文在原因、结果或目的之间转换；
- **比较链**：涉及相似、差异、更多、更少或历史类比；
- **时间变化链**：过去与现在、先后、持续时间或趋势变化；
- **数字数量链**：比例、次数、距离、年龄、年份或数量换写；
- **否定转折链**：not、failed、unable、little、unexpected 等极性信息；
- **观点建议链**：人物或机构的判断、担忧、建议、要求；
- **例证概括链**：题干把具体案例提升为概括性结论；
- **主体/指代链**：题干用身份、群体或代词替换原文主体。

## 运行阶段

### 阶段 0：定位与校验

1. 根据考试级别、年月和套数定位唯一 `exam_id`；
2. 确认存在 matching passage、题号和段落字母；
3. 检查题目数量、段落数量及排序；
4. 默认不读取答案。

### 阶段 1：题干盲标记

只读取 `questions`，不得读取 `passages`、`answer_keys` 或任何已标注证据。

输出：

1. 原题；
2. 带两级优先标记的题目；
3. 可选的锚点说明（主体/动作/对象/限定/逻辑）。

统一按两级格式标记。这一阶段衡量的是“只看题干能否把正确段落召回到3—5个候选中”，不是能否直接猜中答案。

输出前逐条计数；任何标记超过3词都必须拆分或缩短后再显示。

### 阶段 2：展示段落选项

阶段1的标注冻结后，读取 `passages.content_text` 并按原顺序显示全部字母段落。不读取答案表，不突出任何段落，也不暗示正确选项。

默认显示顺序：

1. 段落选项；
2. 原题；
3. 带两级优先标记的题目。

若用户明确要求先练题干标记，可只显示第2、3项，待其确认后再显示段落。

### 阶段 3：用户作答

要求用户按 `36A 37F ...` 提交答案。此阶段仍不读取或显示答案表。

可记录：

- 作答字母；
- 犹豫的题目；
- 用户自选定位词；
- 用时。

### 阶段 4：答案与证据核验

用户提交后才能读取 `answer_keys.answer_value` 和 `answer_text`。

逐题输出：

1. 用户答案与正确字母；
2. 带两级优先标记的题干；
3. 正确段落中的带两级优先标记证据；
4. “题干锚点 ↔ 原文证据”的逐组映射；
5. 主逻辑类型及次逻辑类型；
6. 一句话说明为什么匹配。

只给答案字母不算完成核验。

#### 按选项反向对应版式

严格使用 [paragraph-matching-output-contract.md](paragraph-matching-output-contract.md) 中的“输出模式C：选项反向对应”。该文件是版式、空白项和显示兼容的唯一权威来源。

核验阶段优先使用 `scripts/render_paragraph_mapping.py` 生成有序骨架，减少漏段、乱序、错配或误填未使用段落；该脚本读取答案，盲标与练习阶段禁止调用。

核验顺序固定为：

`主体一致 → 动作/关系一致 → 对象/结果一致 → 时间/数字/极性/范围一致`

任一关键条件冲突，都不能因为出现相同关键词而选择该段落。

### 阶段 5：错因诊断

错误至少归入一种：

- 定位词太泛；
- 只匹配相同单词，未验证语义；
- 漏看否定、比较、时间、数字或范围；
- 主体错配；
- 因果方向反转；
- 例子与结论混淆；
- 被相邻段落或主题相似段落干扰；
- 找到证据但字母抄错；
- 时间分配不当。

### 阶段 6：复盘与迁移

一套题结束后汇总：

- 正确率与用时；
- 各逻辑类型的正确率；
- 最常见错因；
- 用户遗漏的高价值锚点；
- 3—5组可复用的同义替换；
- 下一套训练只强化最弱的1—2类逻辑。

## 功能入口

识别以下意图：

- “画线练习 / 标记练习 / 不看文章先画词” → 阶段1；这些都是触发说法，实际输出使用一级 `【】` 与二级下划线；
- “显示选项 / 显示文章” → 阶段2；
- 用户发送题号加字母 → 阶段3并进入阶段4；
- “显示对应内容 / 原文定位” → 阶段4；
- “为什么选这个 / 逻辑链” → 阶段4的映射与解释；
- “总结错因 / 复盘” → 阶段5—6；
- “下一套 / 随机一套” → 选择未练过的 matching 试卷并从阶段0开始。

## 输出约束

- 清楚标注当前阶段及是否读取答案；
- 每个一级或二级标记严格限制为1—3个单词；每题1个一级、1—3个二级，总计2—4处，并在输出前自检；
- 在答案揭示前，不能通过加粗、排序、提示语或只展示部分段落暗示答案；
- 题干标记与证据标记使用不同小节，不混成一段；
- 数据库文本保持原样，助手增加的说明单独标注；
- 用户要求“不要看答案”时，整个当前练习回合都不访问答案表；
- 数据不完整时停止该题核验并报告缺失字段。

## 后续扩展边界

未来可以为选词填空、仔细阅读、听力、翻译和写作分别新增引用文件。扩展时复用“定位—作答—核验—诊断—迁移”的上层框架，但必须重新定义各题型的数据表、证据单位、标记对象和错因分类；当前段落匹配规则不是通用实现。
