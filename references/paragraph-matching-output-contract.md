# 段落匹配用户体验与输出契约

本文件是段落匹配所有用户可见输出的权威规范。适用于用户拥有或明确授权的本地题库，当前只处理 `question_type = matching`。若本文件与其他示例的显示方式冲突，以本文件为准。

## 目标

让用户只需说出考试年月、套数和简单意图，例如“2026年6月第一套，画线”“显示选项”“原文对应”，系统即可完成任务。不得要求用户反复说明以下既定要求：

- 一级硬定位使用 `【】`；
- 二级语义核验使用可见下划线；
- 每处1—3词；
- 原文与题干对应显示；
- 未使用段落的对应题目留空；
- 练习阶段不泄露答案。

## 默认交互原则

- 用户已提供年月和套数时，直接定位试卷，不再询问“四级还是六级、练什么题型”；
- 已进入段落匹配流程后，后续“继续”“下一套”“显示原文”“解释”等命令沿用当前模式和版式；
- 默认使用中文说明，英语原文保持数据库文本；
- 不输出数据库ID、SQL、内部评分或工具过程，除非用户明确要求；
- 长段落不用表格承载，避免横向滚动和移动端难读；
- 每个标题、原文、对应题目之间保留空行；
- 不用冗长前言，第一行只说明当前模式以及是否读取答案。

## 意图路由

| 用户表达 | 进入模式 | 默认行为 |
|---|---|---|
| “画线”“标记题目”“不看答案”“练这一套” | 盲标练习 | 先只读全部题干并冻结线索集合；若随后显示文章，只调整既有线索的显示优先级；不读答案 |
| “只看题目”“先画题干” | 题干标记 | 只输出原题和两级标记题，不读取段落或答案 |
| “显示选项”“显示文章” | 完整练习 | 输出段落、原题、两级标记题；不读答案 |
| 用户提交 `36A 37F...` | 作答核验 | 读取答案，统计正确率，然后进入选项反向对应 |
| “显示答案”“原文对应”“对应内容”“选项画关键词” | 核验展示 | 若用户明确要求答案，读取答案并使用选项反向对应版式 |
| “为什么”“解释逻辑链” | 深度解释 | 在核验展示后补充锚点映射、改写关系和错因 |
| “下一套”“随机一套” | 新一轮盲标练习 | 选择指定或未练试卷，从盲标状态开始 |

如果一句话同时包含多个意图，按“用户明确指定的输出”优先。例如“显示原文对应，不要解释”只输出反向对应，不追加逻辑分析。

## 状态机与答案隔离

### S0：定位

根据级别、年份、月份、套数定位唯一试卷，检查段落匹配题、题号和段落是否完整。

### S1：盲标

- 只读取 `questions`；
- 不读取 `passages`、`answer_keys` 或答案证据；
- 依据全部题干选出2—4个线索并冻结线索集合；
- 先根据10道题之间的重复情况给出暂定 `【】`：同一实词或短语（含词形变化）出现在至少3题时视为疑似主题词；
- 冻结后不得增删线索；文章出现后只允许根据标题和跨段重复度调整既有线索的一级/二级显示，答案和证据映射不得参与。

### S2：练习

- 可以读取并显示 `passages`；
- 仍不读取 `answer_keys`；
- 根据标题和各段重复情况确认疑似主题词；若某实词或短语出现在标题或至少3个不同段落中，将其确认为主题词并降级，再从已冻结线索中提升更具体的定位词；
- 用户自行作答；
- 不通过段落排序、加粗、删减或提示语暗示答案。

### S3：核验

只有以下情况可以读取 `answer_keys`：

- 用户已经提交答案；
- 用户明确要求答案、原文对应或解析；
- 用户明确要求检查数据库答案。

### S4：复盘

根据用户答案输出正确率、错因、同义改写和下一步训练。用户未要求详细解释时，不强制输出长篇分析。

## 两级标记标准

### 一级硬定位

- 格式：`【...】`；
- 数量：原则上每题1处；
- 长度：1—3个连续英文单词；
- 内容：优先选择独特主体、专名、数字/时间、引号术语或少见的具体名词短语；
- 用途：第一遍快速扫描原文，定位可能出现答案的位置；
- 禁止：全文反复出现的主题词、宽泛主体、抽象且容易同义改写的动作关系。

### 二级语义核验

- 格式：Unicode组合下划线 `U+0332`，不能使用HTML `<u>`；
- 数量：每题1—3处；
- 长度：每处1—3个连续英文单词；
- 内容可分别来自：
  1. 核心动作、状态或关系；
  2. 否定、因果、比较、变化、态度；
  3. 对象/结果和仍需核验的限定条件。

### 总量

- 每题总计2—4处；
- 不为凑数量标记冠词、普通代词、宽泛词或全文主题词；
- 若没有可靠的独特主体，选择最不易被改写的具体对象或事实作为一级；
- 所有标记必须来自原题连续文本，不在题干中发明同义词。

## 输出模式A：仅题干标记

首行：

```text
模式：题干盲标记（未读取段落和答案；【】为暂定定位锚点）
```

随后按题号输出：

```text
36. {原题}
36. {带一级【】和二级下划线的题目}
```

不要输出答案、段落字母或正确段落提示。

## 输出模式B：完整练习

首行：

```text
模式：完整练习（线索已在看文章前冻结；【】已按全文重复度确认；未读取答案）
```

固定顺序：

1. `## 选项`：按原字母顺序显示完整段落，不加答案提示；
2. `## 题目`：按题号显示原始题干；
3. `## 两级标记题目`：显示一级硬定位 `【】` 和二级语义核验下划线；
4. 结尾只提示用户按 `36A 37F...` 作答。

不得把标记直接加到选项原文中，因为练习阶段的原文证据标记会泄露答案。

## 输出模式C：选项反向对应

此模式只用于S3核验状态。按段落字母原顺序显示所有段落，不能只显示被选中的段落。

优先运行 `scripts/render_paragraph_mapping.py --year <YYYY> --month <M> --set <N> --json` 获取确定性的段落顺序、完整原文、题号和空白映射。该脚本会读取答案，只能在S3使用。脚本生成结构后，再加入两级语义标记；不得修改脚本返回的原文和映射关系。

固定模板：

```text
### A

原文：

{完整A段；仅在支持对应题目的证据处加入一级【】和二级下划线}

对应题目：

{完整题号和带两级标记的题干}
```

强制规则：

- 原文必须完整，不能只截证据句；
- 原文措辞、标点和段落顺序必须保持数据库原样，仅可插入显示标记；
- 原文一级 `【】` 与题干一级 `【】` 指向同一定位实体或具体事实，优先使用原词或近似表面形式；
- 原文二级下划线与题干二级下划线对应动作/关系、结果和限定条件；
- 对应题目必须显示完整题号和完整题干，不能只写答案字母；
- 一个段落对应多题时，按题号升序全部列出；
- 没有题目对应的段落仍显示完整原文，但不添加任何证据标记；
- 未使用段落的 `对应题目：` 后必须保持真正空白；
- 空白项禁止写“无”“未使用”“不对应”“—”或解释性文字；
- 除非用户要求，不在每段后重复列出“对应关系”说明。

## 输出模式D：深度解释

在模式C之后，按题号补充：

1. 题干一级定位 ↔ 原文一级定位；
2. 各二级语义线索逐项对应；
3. 同义替换、概括、因果、比较、否定、时间换算或合理推断；
4. 用户错误时说明错因；
5. 不重复整段原文。

## 显示与兼容要求

- `【】`是一级硬定位边界标记，不称为下划线；
- 二级下划线使用Unicode组合下划线，不使用HTML标签；
- 标记不能破坏原词拼写、连字符、撇号和标点；
- 每次输出前检查是否出现超过3词的单个标记；
- 不使用粗体代替一级或二级标记；
- 不用颜色表达优先级，因为不同客户端可能不显示；
- 不把长篇英文塞入Markdown表格；
- 如果Unicode下划线在当前客户端明显错位，保留一级 `【】`，将二级改为 `〔...〕`，并只提示一次，不要求用户重新描述全部规则。

## 数据和异常处理

- 段落标签从原文实际解析，不硬编码A—O；允许A—Z，数据库中存在P段；
- 题目通常是36—45，但必须以数据库记录为准；
- 缺题、缺段落、重复试卷或答案字母不存在时，停止对应题的核验并明确报告字段；
- 不根据常识补造缺失段落、题干或答案；
- 数据库文本与PDF冲突时，先报告差异，再根据用户授权决定是否修正数据库；
- 用户要求“不看答案”时，当前练习回合不得访问答案表，即使答案已存在。

## 输出前自检清单

每次响应前逐项检查：

- [ ] 年份、月份、套数、题型正确；
- [ ] 当前模式及答案读取状态正确；
- [ ] 盲标阶段没有读取段落或答案；
- [ ] 题干盲标模式明确说明 `【】` 只是暂定定位锚点；
- [ ] 完整练习模式已用标题和跨段重复度检查 `【】`，且未读取答案；
- [ ] 每题一级硬定位 `【】` 原则上1处，确认后不是全文通用主题词；
- [ ] 每题二级语义核验下划线1—3处；
- [ ] 每个标记1—3词；
- [ ] 未标记全文通用主题词；
- [ ] 练习模式没有在原文中标证据；
- [ ] 核验模式按全部段落原顺序输出；
- [ ] 原文完整且未改写；
- [ ] 对应题目完整显示；
- [ ] 未使用段落的对应题目保持空白；
- [ ] 没有额外泄露答案或添加用户未要求的长解释。

## 默认延续行为

- 用户说“继续”时，继续当前试卷和当前模式；
- 用户说“下一套”时，沿用两级标记和输出契约；
- 用户说“只看标记”时，只切换显示内容，不改变标记规则；
- 用户说“不要解释”时，保留对应版式，省略模式D；
- 用户临时修改格式时，仅覆盖本轮明确修改的部分，其余仍按本契约执行。

## 接受场景

以下行为必须稳定成立：

1. 用户说“2026年6月第一套，画线”：直接进入S1，不询问通用CET开场问题，不读取答案；
2. 用户说“先列出选项和题目，再列标记题目，不看答案”：先完成并冻结S1线索集合，再读取段落确认主题词，只调整显示优先级，最终按模式B顺序输出；
3. 用户提交 `36C 37I...`：读取答案、给出结果，并按模式C显示全部段落；
4. 用户说“原文对应”：若已授权查看答案，直接使用模式C，不要求再次描述版式；
5. 某段未被任何题目选中：完整显示原文，`对应题目：`后保持空白；
6. 一个段落对应两题：在同一段下按题号升序显示两道完整标记题；
7. 用户说“不要解释”：只输出模式C，不追加锚点映射和错因；
8. 用户说“继续”：沿用当前试卷、两级标记和当前显示模式；
9. Unicode下划线错位：仅将二级标记切换为 `〔...〕`，其他格式保持不变；
10. 数据缺失或冲突：明确指出具体试卷、题号和字段，不猜答案、不补造文本。
11. 题干同时含具体主体和抽象关系时：具体主体或具体名词放入 `【】` 用于扫描，抽象动作/关系使用下划线用于比较；不得反过来只突出容易同义替换的关系词。
12. 题干中的主语后来被发现是标题词或跨段高频词：不新增或删除线索，只把它从 `【】` 降级，并从已冻结线索中提升下一具体定位词；整个过程不得读取答案。
